# Scope and Assumptions

This skill covers `nf-core/rnaseq` 3.22.2 as vendored under
`/root/key_projects/nextmcp/nf_pipeline/rnaseq`. It is intended for runtime work through
nextmcp: plan a run, map user intent to pipeline parameters, launch with `nextflow_run`, review
artifacts, recover prior runs, and troubleshoot failures.

The source basis is the current `nextflow_schema.json`, `README.md`, top-level docs, `main.nf`,
`nextflow.config`, and `interactive.nf`. The complete schema-backed parameter layer is in
`assets/schema-index.yaml` and `assets/schema-groups/*.yaml`; use those files whenever exact type,
default, enum, or description matters.

All runtime paths are server-local. A path such as `<server_input_root>/samplesheet.csv` means a
path on the nextmcp server filesystem, not on the client machine. Use paths returned by nextmcp
tools or paths the user already confirmed exist on the server.

The main supported input is a CSV samplesheet. It may point to FASTQ files or to BAM files
generated by an earlier `nf-core/rnaseq` run. BAM reprocessing should use the documented two-step
workflow: first run with `save_align_intermeds`, then reuse `pipeline_info/samplesheet_with_bams.csv`
with `skip_alignment`. Avoid presenting arbitrary third-party BAMs as a safe default.

The default route is `aligner: star_salmon`. Other supported routes are `star_rsem`, `hisat2`,
Salmon-only or Kallisto-only pseudoalignment with `skip_alignment`, preprocessing-only with both
`skip_alignment` and `skip_pseudo_alignment`, UMI-aware runs, BBSplit filtering, SortMeRNA rRNA
removal, Sentieon STAR acceleration, Kraken2/Bracken screening, and exploratory entries from
`interactive.nf`.

Resource changes belong in `config_files`, not `params`. The source pipeline uses label-based
resources in `conf/base.config`; use a small server-local config with supported Nextflow `process`
settings or `process.resourceLimits` when a cap is needed.
